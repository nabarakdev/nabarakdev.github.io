# Measuring the process

No enterprise speed-up, cost saving or success-rate figure is published without a comparable sample. The public example reports only tests it actually executes.

For future measurements, compare tasks of similar scope and risk and record:

| Measure | Definition |
| --- | --- |
| Lead time | Task intake to a review-ready change, separating waiting time |
| Engineering intervention | Active review and correction time, not just number of prompts |
| Rework | Changes required after review and validation |
| Reliability | Outcomes across the full task sample, including failures |
| Quality | Escaped regressions and acceptance results |
| Cost | Model, tooling and engineering costs per accepted change |

Record the task class, repository count, revision, required checks, actual checks and acceptance state. Do not add overlapping test counts or compare partial runs with completed delivery. A generated report, a passing local suite and an accepted product change are different evidence levels.
